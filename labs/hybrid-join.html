Hybrid Azure AD Join Implementation

Seamless Device Authentication Across On-Premises and Cloud

← Back to Portfolio

Project Overview

Configured hybrid Azure AD join for domain-joined Windows 11 devices in the NigelTech.local environment. This implementation enables seamless single sign-on (SSO) to both on-premises and cloud resources, allowing devices to authenticate to Azure AD while remaining joined to the on-premises Active Directory domain.

Technologies Used: Azure Entra ID, Azure AD Connect, Group Policy, Windows Server 2022 Active Directory, Windows 11

Business Problem

Organizations with hybrid infrastructures need devices to access both on-premises resources (file shares, printers, legacy apps) and cloud services (Microsoft 365, Azure resources). Traditional domain join only provides on-premises authentication, while Azure AD join only provides cloud authentication. Hybrid Azure AD join solves this by enabling dual authentication, providing users seamless access to both environments with a single sign-on experience.

Lab Environment - NigelTech.local

  • Windows Server 2022 Domain Controller (DC01.NigelTech.local)
  • Azure AD Connect server with hybrid configuration
  • Windows 11 Pro domain-joined workstation
  • Azure Entra ID tenant (Premium P1 licensing)
  • Test user accounts synchronized from on-prem to Azure AD

Implementation Steps

Phase 1: Azure AD Connect Configuration

  1. Opened Azure AD Connect wizard on sync server
  2. Selected "Configure device options"
  3. Chose "Configure Hybrid Azure AD join"
  4. Selected target operating system: Windows 10 or later
  5. Configured Service Connection Point (SCP) in on-premises AD
  6. Specified domains for hybrid join deployment
  7. Completed wizard and initiated sync cycle

Phase 2: Group Policy Configuration

  1. Created new GPO: "Hybrid Azure AD Join Configuration"
  2. Navigated to: Computer Configuration → Policies → Administrative Templates → Windows Components → Device Registration
  3. Enabled: "Register domain joined computers as devices"
  4. Linked GPO to the OU containing target workstations
  5. Ran gpupdate /force on test client

Phase 3: Service Connection Point (SCP) Verification

  1. Opened ADSI Edit on domain controller
  2. Connected to Configuration naming context
  3. Navigated to: CN=Configuration → CN=Services → CN=Device Registration Configuration
  4. Verified SCP object contained correct Azure AD tenant information
  5. Confirmed keywords attribute included tenant ID

Phase 4: Device Registration & Testing

  1. Logged into Windows 11 workstation as domain user
  2. Triggered device registration with: dsregcmd /join
  3. Verified status with: dsregcmd /status
  4. Confirmed output showed:
    • AzureAdJoined: YES
    • DomainJoined: YES
    • Device successfully registered in Azure AD

Command output showing AzureAdJoined: YES and DomainJoined: YES, confirming successful hybrid Azure AD join

Phase 5: Azure Portal Validation

  1. Logged into Azure Portal → Entra ID → Devices
  2. Located the registered Windows 11 device
  3. Verified device properties:
    • Join Type: Hybrid Azure AD joined
    • Enabled: Yes
    • MDM: Not enrolled (expected for this lab)
    • Owner: Test user account
  4. Confirmed device could be targeted by conditional access policies

Azure Entra ID Devices view showing registered device with "Hybrid Azure AD joined" status

Challenges & Solutions

Challenge: Initial Device Registration Failed

Issue: After running dsregcmd /join, device showed "DomainJoined: YES" but "AzureAdJoined: NO". Event Viewer showed error 220 - device registration failed to locate SCP.

Solution: Verified SCP creation in Active Directory. The Azure AD Connect wizard had not properly created the SCP object. Manually verified the SCP path in ADSI Edit, found it was missing. Re-ran Azure AD Connect device options wizard, ensuring correct tenant credentials were provided. After completion, SCP appeared correctly and device registration succeeded.

Challenge: Group Policy Not Applying

Issue: GPO for device registration didn't apply to test workstation even after gpupdate /force.

Solution: Ran gpresult /r and discovered the workstation OU had "Block Inheritance" enabled from a previous configuration. Removed block inheritance setting. Also confirmed the device registration GPO was linked to the correct OU and had proper security filtering (applied to "Domain Computers"). After fixing, ran gpupdate /force again and verified with gpresult /r that policy applied successfully.

Key Learning: The Service Connection Point (SCP) is critical for hybrid join. Without it, domain-joined devices cannot discover the Azure AD tenant to register with. Always verify SCP creation in ADSI Edit after running Azure AD Connect configuration. The SCP must be in the Configuration partition to be forest-wide discoverable.

Key Takeaways

  • Authentication flow: Hybrid joined devices authenticate to on-prem AD first, then automatically receive Primary Refresh Token (PRT) from Azure AD for seamless cloud access.
  • Conditional Access enablement: Hybrid join is a prerequisite for device-based conditional access policies. Without it, cannot enforce "require compliant device" rules.
  • Single Sign-On benefit: Users sign in once with domain credentials and automatically access Microsoft 365, Azure resources, and on-prem resources without repeated prompts.
  • Management flexibility: Devices can be managed by both Group Policy (on-prem) and Intune (cloud), allowing gradual migration to modern management.
  • Troubleshooting command: dsregcmd /status is the essential diagnostic tool. Check AzureAdJoined, DomainJoined, and TenantId fields to validate configuration.

Real-World Application

This lab demonstrates capabilities directly applicable to enterprise IAM roles:

  • Configuring device identity in hybrid environments
  • Understanding the relationship between device join states and authentication
  • Troubleshooting device registration issues using Event Viewer and dsregcmd
  • Implementing foundational requirements for zero-trust security (device compliance)
  • Managing Service Connection Points in Active Directory
  • Enabling conditional access policies based on device trust

Integration with Other IAM Components

Hybrid Azure AD join is foundational for several advanced IAM capabilities:

  • Conditional Access: Enables "require hybrid Azure AD joined device" policy condition
  • Windows Hello for Business: Requires hybrid join for certificate trust deployment model
  • Seamless SSO: Works in conjunction with hybrid join for optimal user experience
  • Intune Co-Management: Allows gradual transition from Group Policy to cloud management
