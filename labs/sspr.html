Self-Service Password Reset (SSPR) Implementation

Azure Entra ID with On-Premises Password Writeback

← Back to Portfolio

Project Overview

Implemented Azure AD Self-Service Password Reset with password writeback functionality to on-premises Active Directory in the NigelTech.local hybrid environment. This project demonstrates end-to-end understanding of hybrid identity synchronization, authentication methods, and user self-service capabilities.

Technologies Used: Azure Entra ID, Azure AD Connect (Entra Connect), Windows Server 2022 Active Directory, PowerShell

Business Problem

In enterprise environments, password reset requests create significant helpdesk overhead and user downtime. Users often wait hours for password resets, impacting productivity. SSPR allows users to securely reset their own passwords 24/7, reducing helpdesk tickets by up to 40% and improving user satisfaction.

Lab Environment - NigelTech.local

  • Windows Server 2022 Domain Controller (DC01.NigelTech.local)
  • Azure AD Connect (Entra Connect) synchronization server
  • Windows 11 client (domain-joined test machine)
  • Azure Entra ID tenant with hybrid identity configuration

Implementation Steps

Phase 1: Azure Entra ID SSPR Configuration

  1. Navigated to Azure Portal → Entra ID → Password Reset
  2. Enabled SSPR for "All users"
  3. Configured authentication methods:
    • Email address (primary method)
    • Mobile phone (secondary method)
    • Set requirement: 1 method to reset, 2 methods to register
  4. Enabled "Password writeback" under On-premises integration
  5. Configured registration enforcement to require users to register on next sign-in

Phase 2: Azure AD Connect Password Writeback Setup

  1. Opened Azure AD Connect configuration wizard on sync server
  2. Selected "Configure device options" then backed out to see full options
  3. Selected "Customize synchronization options"
  4. Under "Optional Features" checked "Password writeback"
  5. Verified AD Connect service account permissions in Active Directory
  6. Completed wizard and initiated full synchronization cycle

Phase 3: User Testing & Validation

  1. Created test user account in on-premises Active Directory
  2. Waited for AD Connect sync (verified user appeared in Azure AD)
  3. Logged into Azure Portal as test user → Prompted to register authentication methods
  4. Registered email address and verified with code
  5. Initiated password reset from aka.ms/sspr
  6. Entered username → Verified identity with email code → Set new password
  7. Validated new password worked for:
    • Azure AD sign-in (Office 365 portal)
    • On-premises sign-in (domain-joined Windows 11 workstation)

Challenges & Solutions

Challenge: UPN Suffix Mismatch

Issue: Initial sync showed on-premises user UPN as user@NigelTech.local, but Azure AD required a verified domain suffix. Couldn't complete SSPR registration because UPNs didn't match.

Solution: Added custom UPN suffix in Active Directory Domains and Trusts to match verified Azure domain. Updated test users with PowerShell to use the new UPN suffix. Re-synced with Azure AD Connect. This aligned UPNs between on-prem and cloud.

Key Learning: In hybrid environments, UPN alignment between on-premises AD and Azure AD is critical for SSPR functionality. Always verify UPN suffixes match a verified domain in Azure before enabling SSPR.

Challenge: Password Writeback Delay

Issue: After successful Azure password reset, new password didn't immediately work on domain-joined workstation.

Solution: Discovered this was normal synchronization latency. AD Connect sync cycle runs every 30 minutes by default. For testing, manually triggered delta sync using PowerShell: Start-ADSyncSyncCycle -PolicyType Delta. In production, would set user expectations about 1-2 minute delay.

Key Takeaways

  • Hybrid complexity: Password writeback adds dependencies on network connectivity, AD Connect health, and proper service account permissions. Monitoring is essential.
  • Security design: Requiring 2 methods for registration provides defense-in-depth. If one method is compromised, attacker still can't reset password.
  • User adoption: Registration enforcement is critical. Without it, users won't register and SSPR adoption fails, defeating the purpose.
  • Helpdesk impact: Organizations typically see 40-50% reduction in password reset tickets after SSPR implementation with proper user training.
  • Audit trail: All password resets are logged in Azure AD audit logs, providing complete compliance visibility.
